# jqlite: rewrite for modern browsers

## Context

jqlite is a small, dependency-free jQuery-like DOM library (`$()` selector engine + chainable `ListDOM` collection). The entire current implementation was legacy-oriented: IE compatibility (`attachEvent`/`createEventObject`), vendor-prefixed CSS transitions, `Object.create(Array.prototype)` instead of real array subclassing, manual feature detection for `classList`/`dataset`/`children`/`matches`, and an Angular-1 UMD integration branch. All of that has just been moved into `legacy/` (already staged, not committed) so the repo can carry both the old and new implementation side by side during the rewrite.

This plan replaces it with a from-scratch, modern implementation targeting evergreen browsers only (no IE, no vendor prefixes), while keeping almost all of the documented public API (README.md) working the same way so existing consumers can upgrade with minimal changes.

Two decisions already confirmed with the user:
- **Testing**: Vitest + happy-dom (fast, no real browser launch needed).
- **API scope**: open to trimming legacy-only cruft rather than strict 1:1 parity (specifics below, flagged for final sign-off in this doc).

A prior abandoned attempt exists on `origin/modules` (one WIP commit, just extracted `src/type-cast.js`/`src/utils.js`, never finished) — confirms prior intent, not reused as a template.

## Two bugs found in the legacy code (fix, don't port as-is)

- `eq(pos)`: for negative `pos` it computes `this[this.length - pos]` (e.g. `eq(-1)` on a 5-item list reads index 6 → always `undefined`). Should be `this.length + pos`. README documents negative-index behavior; no test covers it today.
- `val()`: compares `element.nodeName === 'select'`, but `nodeName` is always uppercase (`'SELECT'`) — this branch never fires, in both the getter and setter. No `val()` test exists today either.

Also: `RE_TAG = /^[a-z-_]$/i` (used to fast-path `getElementsByTagName`) matches only single-character tag names — `div`/`ul`/`li`/`span` etc. already silently fall through to `querySelectorAll`. Worth fixing properly (real perf win) rather than porting the dead fast path as-is.

## API trims to confirm (deliberate, not accidental loss)

- Drop `show()`/`hide()`'s opacity-fade animation (`time`/`easing`/`callback` args + vendor-prefixed `transitionKey` detection) → plain `display` toggle. Animation becomes the consumer's job via CSS transitions.
- Drop `css()`'s jQuery-style `'+=5'`/`'-=5'` relative-value string shorthand.
- Drop `wrapAll()` / `unwrap()` — undocumented in README today. **3 of `jqlite-wrap.js`'s 7 tests directly cover these and will be dropped, not ported.**
- Drop the Angular-1 UMD branch (`typeof angular === 'function'`) — ship plain ESM/CJS/global UMD only.
- Drop the dead `_cloneEvents` param on `clone()` (already unimplemented/commented out).
- Open question, flagging rather than deciding: `.html()` currently re-executes `<script>` tags via `eval` after an innerHTML assignment. Unusual and security-sensitive — recommend dropping this behavior too unless there's a known consumer relying on it.

Everything else in README's documented method list keeps its name/behavior, just reimplemented on native modern APIs (`Element.matches`/`.closest`, `classList`, `dataset`, `addEventListener`/`removeEventListener`, `Node.contains`).

## Module structure (`src/`)

```
src/
  internal/
    type-checks.js       # isObject/isFunction/isString/isNumber/isBoolean/isArray/isDate/isRegExp/isElement
    merge.js              # _merge (deep) / _extend (shallow) — powers jqlite.extend + ListDOM#extend
    dedupe.js              # WeakSet-based replacement for the `___found___` marker hack
    fragment.js             # "<div>...</div>" → detached nodes via <template>, not shared auxDiv+innerHTML
    selector-engine.js       # stringMatches()'s branch logic, with RE_TAG fixed
    listener-registry.js      # WeakMap<element, Map<eventName, listener[]>> — replaces $$jqListeners
    event-dispatch.js          # trigger(), via `new Event(name, {bubbles:true, cancelable:true})`
    data-registry.js             # WeakMap<element, Map<key,value>> — replaces $$jqliteData
  list-dom.js                     # class ListDOM extends Array — core + composes method groups
  methods/
    traversal.js                   # get/eq/first/last/find/$/add/each/filter/closest/children/parent/contents/next(All)/prev(All)
    attributes.js                    # attr/removeAttr/prop/val/data/removeData/dataset/removeDataset
    classes.js                         # addClass/removeClass/hasClass/toggleClass (classList only)
    manipulation.js                      # empty/clone/append/appendTo/prepend/before/after/replaceWith/wrap/remove/detach/html/text
    css.js                                 # css/position/offset/width/height/show/hide (plain display toggle)
    events.js                                # on/once/one/off/trigger/stopPropagation/mouseenter/mouseleave/hover + click/focus/blur/submit
  jqlite.js                                  # jqlite(selector, element) factory + statics (extend/isX/ready/noConflict/contains/fn)
  index.js                                    # public entry, default-exports jqlite
```

Grouping mirrors the current file's existing sections (attributes at legacy L729-796, classes L798-897, manipulation L898-1163, css/dimensions L1166-1345, events L1407-1534) — a low-risk mechanical split, not a redesign.

**`class ListDOM extends Array`** replaces `Object.create(Array.prototype)`. This is a real improvement, not just a refactor:
- Index assignment auto-tracks `.length` — all the manual `elems.length = n` bookkeeping scattered through the current code becomes unnecessary.
- `Array.isArray($('div'))` currently returns `false` (not a real array-exotic object); with real subclassing it becomes `true`, and inherited-but-not-overridden `Array.prototype` methods (`.map`, `.slice`, `.concat`, `.some` — already used in a test today) correctly return `ListDOM` instances via `Symbol.species` instead of silently degrading to plain arrays and losing jqlite's methods. Worth calling out as a behavioral change in the changelog.
- Never construct `new ListDOM(n)` with a single number (inherited `Array` constructor quirk: single numeric arg means sparse length, not "array containing n"). Current code already never does this — just don't introduce it later.
- Build target must stay high enough (ES2020+) that esbuild never downlevels `class X extends Array` into an ES5 helper pattern, which cannot correctly subclass builtins.

**Internal modernizations:**
- `$$jqListeners`/`$$jqliteData` DOM-node property stashing → `WeakMap`-based registries (module-private, not attached to elements). Confirmed safe: no test or documented behavior inspects these properties directly.
- Fragment parsing (`"<div>foo</div>"` strings) → `document.createElement('template').content`, replacing the shared `auxDiv.innerHTML` pattern (standard modern idiom, avoids premature image loads).
- `triggerEvent` → `new Event(name, {bubbles: true, cancelable: true})`, keeping the existing `.args`/`.data` custom-property convention so `trigger(name, [a, b])` → `listener(e, a, b)` keeps working.
- All feature-detection branches (`matchesSelectorProp`, `classListEnabled`, `auxDiv.children`/`auxDiv.dataset`/`auxDiv.closest`, `transitionKey`) are deleted outright — just call the native method.

## Build tooling

**esbuild**, via a small `scripts/build.mjs` (JS API, not shell flags), producing:
- `dist/jqlite.mjs` (ESM), `dist/jqlite.cjs` (CJS), `dist/jqlite.global.js` (+`.min.js`, IIFE for `<script>` consumers, `globalName: 'jqlite'` + a footer replicating "assign to `window.$` only if not already taken").
- `target: 'es2020'` explicitly, for the `class extends Array` reason above.

`package.json` gets `"type": "module"`, `"main"`/`"module"`/`"exports"` map (import→mjs, require→cjs), plus `"unpkg"`/`"jsdelivr"` fields pointing at the global build (needed for CDN `<script>` consumers, replacing today's `legacy/index.html` demo pattern).

**Recommend removing `bower.json` entirely** — Bower has been unmaintained for years; not worth updating its `main` field for a library rewrite.

## Test migration

`vitest.config.js` — `environment: 'happy-dom'`, `include: ['test/**/*.test.js']`.

Port the 11 existing Jasmine spec files mechanically: `describe`/`it`/`beforeEach`, the `(done)` async style, and every matcher actually used (`toBe`, `toMatch`, `toBeUndefined` — confirmed by grep, no others, no spy APIs used anywhere) all carry over unchanged in Vitest. The one non-mechanical edit per file: import `$` from `../src/index.js` explicitly instead of relying on karma's injected global.

New coverage needed (didn't exist before): `val()` (zero coverage today), `eq(-1)` regression test for the bug fix, and css/dimensions tests — noting **happy-dom has no real layout engine**, so `position()`/`offset()`/`width()`/`height()` tests can only assert shape/no-throw/`style` was set, not real pixel values.

## Lint / CI

- `eslint.config.js` (flat config, ESLint 9+) replacing both legacy configs: ignores `legacy/**`/`dist/**`, `globals.browser`, `sourceType: 'module'`, carries over `quotes: single`/`semi: always`/`no-unused-vars` (`args: after-used`, `argsIgnorePattern: ^_\w+`). Drops the `angular` global.
- Drop the Makefile for plain npm scripts (`build`/`test`/`lint`) — its main other job (publish/release via a curl+bearer-token hack) is better done in CI.
- Replace `.travis.yml` + `wercker.yml` with one `.github/workflows/ci.yml` (checkout → setup-node → `npm ci` → lint → build → test) — no browser launchers/Xvfb needed since happy-dom runs in plain Node. A separate release workflow on tag push handles `npm publish`.

## Sequencing

1. **Scaffold** (no behavior change): devDependencies (`vitest`, `happy-dom`, `esbuild`, `eslint`, `globals`), configs, npm scripts, empty `src/index.js`, GH Actions workflow. Legacy toolchain keeps working untouched in parallel.
2. **Pure utilities**: `type-checks.js`, `merge.js` — port `jqlite-extend.js` first (zero DOM dependency, proves the pipeline end to end).
3. **Selector engine + `ListDOM` core**: `fragment.js`, `selector-engine.js` (fix `RE_TAG`), `list-dom.js`, `jqlite.js` factory (must preserve `$(existingListDOM) === existingListDOM` identity, tested in `jqlite-$.js`). Port `jqlite-$.js`, then `jqlite-basics.js`/`jqlite-finders.js`/`jqlite-prev-next.js` as `methods/traversal.js` is built. Fix `eq(-1)` here, with a regression test.
4. **Attributes/classes**: `methods/classes.js` (port `jqlite-class.js`), `methods/attributes.js` + `data-registry.js` (port `jqlite-data.js`, fix `val()`, add missing `val()` tests).
5. **Manipulation**: `methods/manipulation.js` (port `jqlite-content.js`, `jqlite-wrap.js` minus the 3 wrapAll/unwrap tests per the trim above — confirm trim before this phase).
6. **Events**: `listener-registry.js`, `event-dispatch.js`, `methods/events.js` — port `jqlite-events.js` last (largest file, 24 tests, most rearchitected).
7. **CSS/dimensions**: `methods/css.js`, dropping `animateFade`/`transitionKey`. No legacy spec to port — net-new tests with the happy-dom layout caveat. Port `jqlite-contains.js` anywhere in this range (no dependencies).
8. **Cutover**: once all ported/trimmed tests pass against `src/` and `npm run build` produces working `dist/`, flip `package.json`'s `main`/`module`/`exports` from `legacy/jqlite.js` to `dist/...` as its own commit. **Bump to `1.0.0`** — flagging for confirmation: runtime floor changes (evergreen-only) and the API surface intentionally shrinks, both breaking changes regardless of today's 0.x version.
9. **Retire legacy**: after cutover ships, delete `legacy/`, `Makefile`, `.travis.yml`, `wercker.yml` together in a follow-up.

## Verification

- `npm test` (Vitest) green at the end of every phase in section "Sequencing" — not just at the end of the rewrite.
- `npm run build` produces `dist/jqlite.mjs`/`.cjs`/`.global.js` and each loads correctly: `node -e "import('./dist/jqlite.mjs').then(...)"` for ESM, `node -e "require('./dist/jqlite.cjs')"` for CJS, and opening a small local HTML page with `<script src="dist/jqlite.global.js">` (replacing `legacy/index.html`'s role) for the browser-global build.
- `npm run lint` clean against `src/` and `test/` (with `legacy/` ignored).
