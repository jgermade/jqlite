# jqlite: rewrite for modern browsers

## Context

jqlite is a small, dependency-free jQuery-like DOM library (`$()` selector engine + chainable `ListDOM` collection). The old implementation was legacy-oriented — IE compatibility, vendor prefixes, manual feature detection everywhere — and has already been moved into `legacy/` (staged, uncommitted) so it stays available as a reference for anyone needing old-browser support, without constraining the rewrite.

This plan is a **clean-slate implementation targeting evergreen browsers only**, built to satisfy the public API documented in README.md — not a port or transliteration of `legacy/jqlite.js`'s internals. The old source is not a design input here; only its documented behavior is.

Two decisions already confirmed with the user:
- **Testing**: Vitest + happy-dom (fast, no real browser launch needed).
- **API scope**: open to trimming legacy-only cruft rather than strict 1:1 parity (specifics below).

## The API contract (from README.md)

Implement, on a chainable collection returned by `$(selector)`:

- **Relative queries**: `get`, `eq`, `first`, `last`, `find`, `closest`
- **Traversal** (documented as missing in the old README, worth finally landing cleanly): `prev`, `prevAll`, `next`, `nextAll`, `parent`, `children`
- **Classes**: `addClass`, `removeClass`, `toggleClass`, `hasClass`
- **Moving/creating DOM**: `append`, `prepend`, `before`, `after`, `wrap`, `replaceWith`, `detach`, `remove`
- **Getters/setters**: `val`, `html`, `text`, `contents`, `prop`, `attr`, `removeAttr`, `data`, `removeData`, `empty`
- **Misc**: `clone`, `css`
- **Events**: `on`, `off`, `one`, `trigger`, `click`/`focus`/`blur`/`submit` shorthands
- Root-level: `$(selector)`, `$('<div>...</div>')` HTML-fragment construction, `$.contains(a, b)`, `ready()`

Correctness requirements worth stating explicitly since they're easy to get subtly wrong:
- `eq(pos)` with negative `pos` counts backward from the last element (documented behavior) — verify with a test, since this is a common off-by-one spot.
- `val()` must work correctly for `<select>` (returns the selected option's value) as well as plain inputs — case-sensitivity of tag/node name checks is a common trap, worth an explicit test.
- `find('> selector')` (direct-child combinator shorthand) and selector dispatch generally should just delegate to `querySelectorAll`/`matches`/`closest` — no need for hand-rolled per-selector-shape branching now that these are fast and universal.

## API trims (deliberate scope reduction vs. old jQuery-parity feature set)

- No animated `show()`/`hide()` — plain `display` toggle. Animation is the consumer's job via CSS transitions.
- No `css()` `'+=5'`/`'-=5'` relative-value shorthand.
- No `wrapAll()` / `unwrap()` (never documented in README).
- No framework-specific module integration (e.g. Angular constants) — ship plain ESM + CJS + browser-global builds.
- No script re-execution inside `.html()` — setting HTML should not `eval` embedded `<script>` tags.

Everything else in the contract above should work exactly as documented, built on native modern APIs (`Element.matches`/`.closest`, `classList`, `dataset`, `addEventListener`/`removeEventListener`, `Node.contains`, `ParentNode` methods).

## Architecture (`src/`)

```
src/
  internal/
    type-checks.js       # isObject/isFunction/isString/isNumber/isBoolean/isArray/isDate/isRegExp/isElement
    merge.js              # deep/shallow object merge, powers `$.extend` / collection `.extend`
    fragment.js            # HTML-string -> detached nodes, via <template>
    listener-registry.js     # WeakMap<element, Map<eventName, listener[]>> for on/off/one bookkeeping
    data-registry.js           # WeakMap<element, Map<key, value>> backing .data()/.removeData()
  list-dom.js                   # class ListDOM extends Array — the collection type, composes method groups
  methods/
    traversal.js                 # get/eq/first/last/find/add/each/filter/closest/children/parent/contents/next(All)/prev(All)
    attributes.js                  # attr/removeAttr/prop/val/data/removeData
    classes.js                       # addClass/removeClass/hasClass/toggleClass
    manipulation.js                    # empty/clone/append/appendTo/prepend/before/after/replaceWith/wrap/remove/detach/html/text
    css.js                               # css/position/offset/width/height/show/hide (plain display toggle)
    events.js                              # on/off/one/trigger/hover + click/focus/blur/submit shorthands
  jqlite.js                                # the $(selector, context) factory + statics ($.extend/$.isX/$.ready/$.noConflict/$.contains)
  index.js                                  # public entry point, default-exports $
```

`class ListDOM extends Array` (real array subclassing) is the key architectural choice: index assignment auto-tracks `.length`, `Array.isArray($(...))` is `true`, and inherited `Array.prototype` methods (`.map`, `.slice`, `.some`, etc.) correctly return `ListDOM` instances via `Symbol.species` instead of degrading to plain arrays. Requires the build target to stay at ES2020+ so no bundler ever downlevels `class extends Array` into a helper pattern that can't subclass builtins correctly.

Internal state (event listeners registered for `.off()`/`.one()`, and `.data()` storage) lives in module-private `WeakMap`s keyed by element, not as properties stamped onto DOM nodes — avoids leaking internal bookkeeping onto arbitrary elements and gets garbage-collected automatically.

## Build tooling

**esbuild**, via a small `scripts/build.mjs`, producing:
- `dist/jqlite.mjs` (ESM), `dist/jqlite.cjs` (CJS), `dist/jqlite.global.js` (+ minified, IIFE for plain `<script>` consumers, exposing `window.$`/`window.jqlite` — `$` only if not already taken).
- `target: 'es2020'` explicitly.

`package.json`: `"type": "module"`, `"main"`/`"module"`/`"exports"` map (import → mjs, require → cjs), plus `"unpkg"`/`"jsdelivr"` fields pointing at the global build for CDN `<script>` consumers.

Recommend removing `bower.json` entirely — Bower has been unmaintained for years.

## Testing

Vitest + happy-dom (`vitest.config.js`: `environment: 'happy-dom'`). Write a fresh test suite organized by the same `methods/*` grouping, covering every method in the API contract above directly against its documented behavior (README + the trims list), not against the old implementation's internals. `legacy/tests/*.js` can be consulted for edge cases/inspiration but is not a checklist to reproduce line-for-line.

Note: happy-dom has no real layout engine, so `position()`/`offset()`/`width()`/`height()` tests can only assert shape/no-throw/that `style` was set correctly — not real pixel values.

## Lint / CI

- `eslint.config.js` (flat config, ESLint 9+): ignores `legacy/**`/`dist/**`, `globals.browser`, `sourceType: 'module'`, `quotes: single`/`semi: always`/`no-unused-vars`.
- Drop the Makefile for plain npm scripts (`build`/`test`/`lint`).
- Replace `.travis.yml` + `wercker.yml` with one `.github/workflows/ci.yml` (checkout → setup-node → `npm ci` → lint → build → test). No browser launchers needed since happy-dom runs in plain Node. A separate release workflow on tag push handles `npm publish`.

## Sequencing

1. **Scaffold**: devDependencies (`vitest`, `happy-dom`, `esbuild`, `eslint`, `globals`), configs, npm scripts, empty `src/index.js`, GH Actions workflow. Legacy toolchain keeps working untouched in parallel.
2. **Core**: `type-checks.js`, `merge.js`, `fragment.js`, `list-dom.js`, the `$(selector, context)` factory (must preserve `$(existingCollection) === existingCollection` identity).
3. **Traversal**: `methods/traversal.js` + tests — `get`/`eq`/`first`/`last`/`find`/`closest`/`children`/`parent`/`contents`/`next(All)`/`prev(All)`.
4. **Attributes/classes**: `methods/attributes.js` (+ `data-registry.js`), `methods/classes.js` + tests.
5. **Manipulation**: `methods/manipulation.js` + tests.
6. **Events**: `listener-registry.js`, `methods/events.js` + tests.
7. **CSS/dimensions**: `methods/css.js` + tests (with the happy-dom layout caveat noted above).
8. **Cutover**: once the full suite passes against `src/` and `npm run build` produces working `dist/`, flip `package.json`'s `main`/`module`/`exports` from `legacy/jqlite.js` to `dist/...`, as its own commit. Bump to `1.0.0` — the runtime floor and API surface both change in breaking ways versus today's 0.x line.
9. **Retire legacy**: after cutover ships, delete `legacy/`, `Makefile`, `.travis.yml`, `wercker.yml` together in a follow-up.

## Verification

- `npm test` (Vitest) green at the end of every phase above.
- `npm run build` produces `dist/jqlite.mjs`/`.cjs`/`.global.js`, each loading correctly (ESM import, CJS require, and a plain HTML page with `<script src="dist/jqlite.global.js">`).
- `npm run lint` clean against `src/` and `test/`.
